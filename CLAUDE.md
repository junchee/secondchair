# Meeting Copilot (Jun)

Mac app (product name: secondchair; Jun named the current beta "hajung") that listens to Zoom/Teams/Meet audio and shows, in two columns, a live transcript and context-aware suggestions (related prep material, what to say next). Prep material and meeting goals can be uploaded before the meeting.

## Decisions
- v1: Python backend + browser UI on localhost. Later port to a native Swift app (per-app audio capture via ScreenCaptureKit, overlay window hidden from screen share, menu bar).
- Audio: the user's audio settings stay their own. Only while secondchair runs, `native/route` (Swift) adds a temporary multi-output device (real output + BlackHole 2ch) as the default output and follows device changes; it restores and deletes it on exit. Mic captured separately. Target design (Core Audio process tap, no device changes at all): `docs/audio_routing.md`.
- STT: local Whisper (Apple M1).
- LLM: Qwen via OpenRouter, key in env var `OPENROUTER_API_KEY` (in `~/.zshrc`). Zero data retention is enforced per request (`provider: {zdr: true, data_collection: deny}`); Alibaba-hosted Qwen flash models are refused under it, open-weight Qwen on ZDR hosts works.
- Output: meetings mostly English. Bidirectional English <-> Korean translation per line is an option (on by default in `app.py`, `--translate` in the terminal versions); it comes before "what to say next" suggestions.
- Path to an app: (1) browser version, needs the venv and BlackHole; (2) Python bundled into a .app (no Python install, BlackHole still needed); (3) native Swift app with a process tap (no BlackHole).
- Participants will be told the meeting is being transcribed.

Step 4b built (2026-10-15), Jun's request: the other side is only translated on the page; only Jun's speech is voiced.
- Main flow (Jun's decision 2026-10-15): the computer voice is rare; the main use is Jun reading the translated English himself. So: Jun's Korean (spoken or typed) is translated into the "English to say" box in every mode, with Copy and Clear; to speak Korean without the meeting hearing it, Jun mutes Zoom first (typing needs no mute). The computer voice is the **Avatar voice (beta)**, kept at the very bottom in a small collapsed "Beta" footer: Avatar voice switch (mode "interpret" in code), voice picker + preview, "Hear it too" monitor and volume, Zoom/BlackHole 16ch note. When it is on, a header chip says "Avatar voice on", Speak appears, and only "오케이"/Speak send the English by computer voice (the meeting then hears only the computer voice). There is no keyboard shortcut for it, so it cannot be switched on by accident. With it off, BlackHole 16ch passes Jun's real mic through.
- `voice_out.py`: a virtual mic ("BlackHole 16ch", override with `SECONDCHAIR_VOICE_DEVICE`) that Jun picks as the microphone in Zoom/Teams. "My voice" mode passes the real mic through; "Interpret" mode holds the mic back, collects translations of Jun's Korean MIC lines as an English draft, and speaks it with a macOS voice (`say`, best installed English voice) when Jun says "오케이" (or presses Enter, after editing if wanted). The monitor (on by default, 50%) plays the same speech in Jun's headphones via `monitor_play.py` on the real device, not the default output, which also feeds BlackHole 2ch. "다시" clears; a Korean line more than 3 s after the draft's last line replaces the draft (Jun said it again). Needs headphones (mic is off on speakers) and translation on.
- Page: My voice / Interpret (I), Settings panel (longest line 4-20 s, pause 0.2-1.5 s, monitor; live), Summary (S), Stop (same clean shutdown as Ctrl+C; closing the page does not stop secondchair).
- Composer (one box at the bottom, Jun's approved design): "English to say", filled by the Interpret voice draft or by typing. Typing (`/`): Korean -> short spoken English to read out (Speak can also voice it); English -> Korean to check meaning. Uses the last 8 transcript lines as context (`translate.translate_typed`). Typed text is not recorded or summarized: it was not said. Last 5 typed results as chips. A voice draft never overwrites typed or edited text; "Load new voice draft" offers it.
- Summary during the meeting (Jun's approved design): right-side panel, always the whole conversation so far, one request at a time, no automatic summaries. Each leaves a "Summary at HH:MM" note in the transcript to reopen it, and is saved in the `.md` where it was made ("중간 요약").
- `record.py`: every session saved in `transcripts/` (gitignored): `.jsonl` as it happens, `.md` at stop with final translations. `summary.py`: Korean summary (핵심 요약, 결정 사항, 할 일, 열린 질문) with `qwen/qwen3.5-35b-a3b`; the final one goes on top of the `.md`.
- Ask about the meeting (Jun's approved design): the bottom line has Translate | Ask (or start with `?`, key `?`). The answer comes in the right panel's Ask tab, in Korean, only from the whole conversation so far (`summary.answer`, `qwen3.5-35b-a3b`, last 3 Q&A kept for follow-ups). Says "대화에서 찾을 수 없습니다" when the transcript lacks it. Questions and answers are not recorded.
- Voice picker (Jun's approved design): Settings > "Voice in the meeting" lists the English voices installed (`voice_out.list_voices`: novelty/robotic ones left out; gender from a known-names table because `say` does not report it). Choosing one previews it in Jun's headphones only; the choice is saved in `user_settings.json` (gitignored). Default: best Premium/Enhanced voice, else Samantha. Only standard voices are installed so far; Jun can add Premium ones in System Settings > Accessibility > Spoken Content > Manage Voices. Premium/cloud voices are a commercial idea (see memory).
- Saved settings (Jun's request after setting the longest line to 7 s): `prefs.py` keeps `user_settings.json` (gitignored): longest line, pause length, mic filter, translation on/off (a missing API key does not overwrite the wish), the voice, the monitor and its volume. Loaded at start, saved the moment the page changes one; a missing/damaged file or bad values fall back to defaults. The terminal versions (`transcribe_small.py`...) do not read or write it. Tested with a temporary file.
- Mic noise filter (from Jun's log: five phantom "Thank you." MIC lines in 3 minutes while Jun was silent): each segment carries its speech level (RMS over speech frames); MIC segments below the setting's level are dropped before Whisper (Settings > My microphone: Off 0 / Normal 0.006 / Strong 0.015). MIC lines are saved with `level` in the .jsonl so the thresholds can be tuned from Jun's real sessions. Synthetic test only (noise bursts 0.004 dropped, speech 0.012+ kept at Normal); real mic levels not yet measured.
- Meetings (Jun's design, 2026-10-15): one program run holds many meetings. Buttons **Start | Pause/Resume | End** (one toggle for Pause/Resume), and **Quit secondchair** at the bottom of Settings. `transcribe_stream.Engine` is the state machine: idle -> running <-> paused -> ending -> idle. Start: new transcript files (`Recorder.begin`), the page's history is reset (`Hub.reset`), fresh capture streams and a new output route, translator context cleared, line ids restart. Pause: keeps the output connected, drops audio (nothing transcribed or recorded), segmenters reset on resume. End: closes the streams, restores the sound output first, then makes the final summary and saves (`Meeting.finish`). The virtual microphone (BlackHole 16ch passthrough, `VoiceOut`) lives for the whole run so Zoom keeps hearing Jun after End. Quit (page, Ctrl+C, SIGTERM, closing the Terminal window) ends a running or paused meeting properly first. The program starts a meeting automatically at launch. After End the finished meeting stays on the page and Summary/Ask still work until the next Start. Tested with fake audio: state flow, pause drops audio, route kept through Pause and released at End, second meeting restarts ids, quit while paused saves; the page's buttons, banner, clearing and Quit. Not tested with real devices.
