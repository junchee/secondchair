## Swift prototype AnneProto (2026-11-05): WhisperKit + system sound without BlackHole
- Source `proto/anneproto/` (SwiftPM, builds with the Command Line Tools only, 2-3 min first time; pack and sign as `~/AnneProto/AnneProto.app`, Info.plist needs `NSAudioCaptureUsageDescription`, `LSMinimumSystemVersion` 14.2). Model and tokenizer are read from `~/AnneProto/model` and `~/AnneProto/tokenizer` (WhisperKit must be given `tokenizerFolder`, else it waits on the network). Each line's sound is saved to `~/AnneProto/lines/NNN.wav`, results go to `~/Library/Logs/AnneProto.log`.
- **Sound capture works**: Core Audio process tap (`native/audiotap.swift` idea), no BlackHole, no output change, volume keys fine. The permission belongs to the app that runs the code: from the Claude app's Bash tool the tap returned only zeros, from the Terminal panel the prompt appeared; the `.app` asks by itself.
- **Measured** (same 4 s cuts, 4.0 s / 0.2 s): WhisperKit small 0.61 s per line (Korean 0.65 s, max 1.9 s), memory 88-106 MB (CPU side only, not the Neural Engine); mlx-whisper small 1.1-1.5 s, about 530 MB. On 19 identical Korean news lines: 12 same text, 7 differ only at the edges (WhisperKit 11.2 s vs mlx 16.2 s in total). Synthetic clips: 12 of 15 identical. Quality is the same class; a real name or loan word ("도대체", "연봉", "gnit") was heard wrongly by WhisperKit; not compared with mlx on the same audio yet.
- **First start** of a new app compiles the model for the Neural Engine: 157 s once, then 2.3 s. Needs a progress display. WhisperKit shows Whisper's made-up captions (`[구독 / 좋아요]`, `[끝]`, `[Music]`): Anne's noise filter must be ported or applied in Python. Whether Briefing terms can go in as a prompt is not checked.
- **Plan (Jun OK'd 2026-11-05):** hybrid: Swift does capture and speech to text (system sound "상대" plus Jun's mic "나"), the Python server keeps bubbles, translation, summary, page. Python goes inside the app (standalone Python, no install for the user). Order: mic in the prototype -> send lines to the Python server -> compare on real meetings -> pack (with step 2 of Anne.app). Full Swift later, if worth it.
- **BUILT 2026-11-05 (step 1 of the plan): `app.py --remote-speech`** (needs env `ANNE_TOKEN`; `remote.py` `RemoteEngine`): no Whisper, mic, BlackHole or route; the app posts each finished line to `POST /line` with header `X-Anne-Token` {source SYSTEM|MIC, lang en|ko, text, level?, avg_logprob?, no_speech_prob?, language_share?}; the same noise rules apply here (`keep_text`, plus lines made only of a bracketed sound label like `[Music]`, `[구독 / 좋아요]`), then bubbles, translation, page, saving as before. Start/Pause/End still come from the page (the app listens to `session` events). Tested on a copy in port 8799 with fake lines and the real translator: token and format checks, bubble joining, mic level drop, pause; NOT with the Swift app yet. `app.py` still imports `transcribe_stream` (so mlx is still loaded): split that out when the Python goes into the app.

- **Swift speech (Anne.app, 2026-11-05): Anne.app itself hears the sound (`app/Sources/Anne/Speech.swift`, SwiftPM package in `app/`, built by `app/build.sh`) and posts lines to the Python server started with `--remote-speech`.** Models are read from `~/AnneProto/{model,tokenizer,turbo}` (temporary); turbo is used when present (`ANNE_MODEL=small|turbo`, `ANNE_SPEECH=python` for the old way). Measured: turbo reads about 1.3 s per line, small about 0.6 s; turbo is clearly more exact (small dropped lines, invented text, "불이" for "불만이"). Compile on first start of an app: small 3 min, turbo 18 min on this 8 GB Mac (once; OS updates may repeat it). Plan: 16 GB and more -> turbo, 8 GB -> small; progress screen and compile at install time. **Bugs to remember (details in memory `project-swift-speech-pitfalls`):** audio lost while Whisper works; a cruder segmenter than Python's (now ported); wrong language label on short lines (language is taken from the text); double language detection; 48->16 kHz skipping; no `settings` event before Start (terms screen never showed); `tokenizerFolder` needed. Not yet tested: Jun's mic with this build, a real Zoom/Teams call, the new segmenter on real speech.

- **DESIGN (Jun, 2026-11-05): sentence-based streaming for the Swift speech (shown, waiting for Jun's go).** Cause of the poor text: lines of 3-4 s are too short for Whisper (the same sound read as one 10-14 s piece came out right, e.g. "파기환송한 대법원 전원합의체 판결을 근거로"); no sound is lost any more. Plan: (1) always keep all sound; keep an "open sentence window" (sound since the last confirmed sentence, max 15-20 s) and run the whole window through the model about every second; a sentence followed by more text is confirmed, the last one when it ends with . ? ! or 다/요 and a 0.6 s pause follows (or 25 s); confirming moves the window start to that sentence's end (segment times). Send confirmed sentences as `line`, the unfinished tail as `partial`. (2) then drafts: first words shown at once in grey (small model for drafts, turbo for confirming: only on 16 GB and more; check memory). (3) then translation that is revised step by step: draft translation only when the draft grew by 4+ words and at most every 2 s; the previous 1-2 sentences go in as context and the earlier translation as reference; a confirmed sentence gets a last pass. Risks: load on 8 GB, more translation calls (cost x2-3, measure), sentence-end guesses in Korean. Do step (1) first.
